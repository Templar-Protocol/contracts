## Tradeoff assessment

- Conventional Owner administration remains separate from explicit Uploader/Deployer membership, avoiding an Owner→Admin migration or synthetic membership semantics.
- NEP-145 pre-funding makes original-payer ownership explicit for pending and retained storage. The ADR acknowledges the resulting funding burden, including possible payer top-ups during approval and separate protocol-owned backing.
- Pending-only hash uniqueness permits approved aliases without introducing a historical index, scans, or migration bootstrap.
- Handle-only migration preserves historical data and Owner slots without entry rewriting.
- Legacy registration remains available during caller migration. Gateway/tmplrmgr UX, production execution, and human acceptance remain outside this deliverable.

These are deliberate decisions consistent with the supplied decision inventory, not unresolved blockers.

Failed deployment/global-probe cleanup avoids a new solvency assertion that would strand reservations during an existing shortfall. The atomic deploy/migrate/storage-check sequence addresses upgrade-related consumption of user backing.

## Consequence simulations

The following are source-based control-flow simulations, not newly executed tests.

| Scenario | Assessment |
|---|---|
| An Uploader or Deployer attempts approval or upgrade | Owner checks remain separate from explicit membership. Action authorization uses predecessor identity; Owner’s bypass does not create synthetic membership. The separation is consistent with the ADR. |
| Ownership transfers or an Uploader loses its role while code remains stored | Pending and retained charges still identify the original payer. Owner-authorized removal credits that payer, not the remover or successor Owner; withdrawal remains predecessor-scoped and independent of roles. |
| Uploaded approval requires additional storage funding | Approval measures the conversion’s net storage change and adjusts the original payer’s available credit. The DAO’s one yocto is confirmation, not storage funding. The ADR correctly identifies payer top-up as an operational consequence. |

| Migration or the post-upgrade backing check fails | Deploy/migrate/check are chained in one self-receipt for the inspected V2 upgrade path. The sandbox test source checks rollback of code mode, storage usage, and payer credit, rather than relying only on matching code hashes. |
