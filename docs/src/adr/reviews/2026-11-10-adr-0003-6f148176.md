## Compatibility decision

`RegistryEvent::Deployed` 1.1.0 has nullable `deployer` and `full_access_keys`. New finalizer calls carry optional, serde-defaulted metadata and emit `Some` values, including `Some([])` for an explicitly empty key list. Legacy in-flight calls lacking that metadata decode as `None` and emit explicit `null`; no provenance is invented. The `Deployment` view remains unchanged.

Implementation #708 must thread the metadata through successful finalization and test exact new and legacy event payloads before merging. Registry-DAO gas-override support remains required before rollout. Neither implementation obligation is claimed complete by this ADR branch.

## Independent verdicts

- **Architect:** APPROVE. The amendment preserves new-deployment provenance, distinguishes it from unavailable legacy provenance, and makes callback deserialization and pre-merge evidence explicit without changing the owner decisions.
- **Critic:** APPROVE. Optional trailing callback metadata is technically compatible with legacy JSON, and the `Some`/`None` event representation resolves the prior callback-provenance concern without contradicting the unchanged view or in-flight acceptance scenario.
- **Consensus:** APPROVED for candidate `6f148176` and ADR blob `6c0b46a6`; not implementation-merge or production approval.
