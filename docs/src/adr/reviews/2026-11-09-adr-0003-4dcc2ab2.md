## Requirement coverage

- **Authority:** Conventional Owner derivation, storage slots, two-step transfer, and renunciation are retained intentionally. Uploader/Deployer membership is explicit; administration remains Owner-only. The current decision inventory—not the superseded implementation plan—governs these choices.
- **Wire and events:** Borsh upload input, hash-only JSON approval variants, pinned role/source discriminants, and conventional `role_set` payloads are represented in the inspected definitions and compatibility assertions.
- **Accounting:** NEP-145 prefunding covers measured pending storage and retained per-version charges. Releases return credit to the original payer. Administrative withdrawal and forced unregistration are excluded.
- **Approval and legacy behavior:** Both approval variants have consuming branches. Global approval reuses registration/probe/finalization. All three legacy source variants remain handled; successful keys stay occupied, while failed probes permit retry.
- **Migration:** Existing collection handles and prefixes are preserved without history traversal or rewriting. New accounting structures start empty; historical code stays registry-funded.
- **Protocol backing:** Solvency includes physical storage, available user credit, remaining Owner-slot capacity, and in-flight final deployment-record reserves. Reservation-bearing entries are handled by views and callback finalization.
- **Rollout and scope:** Both pre- and post-deletion proofs are mandatory. Production execution, gateway/tmplrmgr UX, human acceptance, and implementation merge remain deferred.

## Alternative fairness

The alternatives address the actual decision boundaries and acknowledge meaningful costs:

- **Owner-only/deposit-based operation** offers fewer interfaces, but retains concentrated authority and less explicit retained-payer accounting.
- **RBAC Admin replacing Owner** could represent administration, but adds storage/API/handoff migration without improving the required capability separation.
- **Historical hash exclusion/indexing** changes alias policy and adds index bootstrap or history-scan costs. Pending-only uniqueness deliberately avoids both.
- **Forced unregistration or Owner withdrawal** simplifies exceptional administration but conflicts with the selected original-payer guarantee.
- **Historical entry rewriting** adds migration work and failure surface without being necessary for this cutover.

The selected design is not presented as cost-free: the ADR acknowledges ledger complexity, uploader top-ups, protocol-owned backing, and Deployer trust.
